# PDI v0.6.0

> **Release authority:** this document describes PDI v0.6.0. The exact
> annotated Git tag `v0.6.0` is authoritative: without that tag, a source
> commit remains unreleased.

PDI v0.6.0 turns the previously self-hosted engineering milestone into a public,
provider-independent project boundary. It keeps PDI Core independent of storage
Providers and consumer runtimes while making a clean source checkout usable by
another technically competent self-hosting operator.

## Product capabilities

- Nextcloud, Immich, and bounded Gmail Adapters normalize Provider state into
  stable Resources, Sources, Blobs, and deterministic Observations.
- Nextcloud traversal streams facts and safely marks mutable-provider races
  non-authoritative without deactivating unseen Sources.
- Query, Retrieval, Observation, Resource Access, Data Status, and read-only
  MCP boundaries expose PDI without database, ORM, or Provider credentials.
- Typed Resources, minimal Person identity, and the dedicated Provider-derived
  `Resource depicts Person` relation remain narrow World Model capabilities.

Detailed pre-release operational evidence is preserved in the
[archived engineering milestone](../archive/pdi/v0.6-engineering-milestone.md).

## Public self-host boundary

- Python 3.13, PostgreSQL 16, Alembic, and one configured Provider form the
  manual source-install contract.
- Provider configuration is independent: selecting Nextcloud, Immich, or the
  explicit Gmail pilot does not require unrelated credentials.
- `pdi sync` and `pdi mcp` are stable public conveniences over the existing
  application composition paths.
- Generic systemd assets use a documented `/opt/pdi` reference layout, and the
  PostgreSQL Compose example binds to loopback by default.
- Jarvis remains an optional reference consumer and is not required to install
  or use PDI.

## Public repository readiness

- Public documentation establishes PDI as Personal Digital Infrastructure,
  separates private operations, and contains no real Provider-derived fixture
  data.
- `CONTRIBUTING.md` and `SECURITY.md` define contribution, test-isolation,
  credential, personal-data, and consumer-boundary rules.
- GitHub Actions cover Python 3.13 host-safe tests, isolated PostgreSQL 16
  migrations/integration, clean package installation, and redacted current/
  history Gitleaks scanning.
- `constraints/python3.13.txt` records the reviewed transitive dependency set;
  `pyproject.toml` remains the direct supported-range authority.
- Standard sdist and wheel artifacts build successfully. The sdist supports the
  source/self-host migration path; the wheel supports `pdi` CLI and MCP runtime
  use but does not claim standalone Alembic migrations.

## Known limitations

- The project remains active, pre-1.0 software; public installation is manual,
  not one-click.
- Gmail remains an explicit single-account pilot with no unattended scheduler.
- Nextcloud metadata traversal remains sequential even though fact processing
  now streams.
- No PyPI publication, DeepSeek Harness integration, or Jarvis split is part
  of v0.6.0.
