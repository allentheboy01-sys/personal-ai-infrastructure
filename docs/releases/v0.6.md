# PDI v0.6 — Operational Hardening

## Frozen production capabilities

- Data Status & Freshness V0.1: historical PipelineRun ledger, static
  ten-pipeline registry, formal single-lock runner, derived freshness signals,
  and `pdi_get_data_status` as the eighth read-only MCP Tool.
- Person Identity V0.1: 417 stable PDI Persons mapped from the standard Immich
  enumerable People inventory, without names, face data, public references, or
  scheduling.
- Resource-Person Relation V0.1: one dedicated provider-owned `Resource depicts
  Person` table with 10,460 active production relations across 5,267 Resources
  and 417 Persons.
- Typed Resource V0.1: `assets.id` remains canonical while
  `assets.resource_type` explicitly distinguishes `file` and `message`.
- Gmail Provider V0.1: single-account, read-only full enumeration into Message
  Resources with RAW RFC 2822 Blobs and four deterministic observations.

Resource-Person relations contain only Resource identity, Person identity,
Provider provenance, and inactive lifecycle. The feature adds no relation UUID,
generic graph, face/vector data, confidence, MCP capability, systemd unit,
timer, or PipelineRun entry. The explicit command
`python -m pdi.resource_person_relation` performs one complete reconciliation.

Production migration head is `3b1e6f8a4c20`. All 15,325 existing Resources were
deterministically migrated to `file`; that migration itself created no Message
rows. Blob remains
mandatory, file hash deduplication is unchanged, and separate Provider Message
identities never auto-merge by global content hash. Observation, Relation,
public Resource references and MCP remain unchanged.

Gmail production validation created 283 Message Resources, 283 active Gmail
Sources, 283/283 RFC 2822 Blob coverage, and 1,132 current observations. The
second formal sync produced zero actions; the second enrichment processed zero
and skipped all 283 Resources. The registry now tracks 10 pipelines, including
`provider.gmail.sync` and dependent `enrichment.gmail_metadata`; MCP remains
eight read-only Tools. Gmail API writes were zero. V0.1 is single-account only,
has no scheduler/timer, and remains unsuitable for unattended operation while
the OAuth application is in Testing.

Initial and immediate idempotency
syncs passed with zero duplicates or orphans. The 114 audited pairs associated
with 84 Immich Person identities outside Person Identity V0.1 remain excluded.

Final Gmail validation completed host-native with `466 passed, 98 skipped`
in the host-safe/default suite and `99 passed, 2 skipped` in the isolated
PostgreSQL suite. Host-native execution is required because the Codex command
sandbox blocks the MCP SDK `Client.call_tool` worker path; standalone and
minimal pytest controls pass normally outside that sandbox.
