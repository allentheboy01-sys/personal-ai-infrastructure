# PDI v0.6 — Operational Hardening

## Frozen production capabilities

- Data Status & Freshness V0.1: historical PipelineRun ledger, static
  eight-pipeline registry, formal single-lock runner, derived freshness signals,
  and `pdi_get_data_status` as the eighth read-only MCP Tool.
- Person Identity V0.1: 417 stable PDI Persons mapped from the standard Immich
  enumerable People inventory, without names, face data, public references, or
  scheduling.
- Resource-Person Relation V0.1: one dedicated provider-owned `Resource depicts
  Person` table with 10,460 active production relations across 5,267 Resources
  and 417 Persons.

Resource-Person relations contain only Resource identity, Person identity,
Provider provenance, and inactive lifecycle. The feature adds no relation UUID,
generic graph, face/vector data, confidence, MCP capability, systemd unit,
timer, or PipelineRun entry. The explicit command
`python -m pdi.resource_person_relation` performs one complete reconciliation.

Production migration head is `9c4e1a7b2d30`. Initial and immediate idempotency
syncs passed with zero duplicates or orphans. The 114 audited pairs associated
with 84 Immich Person identities outside Person Identity V0.1 remain excluded.

Validation completed with `447 passed` in the host-safe/default suite and
`93 passed, 2 skipped` in the isolated PostgreSQL suite.
