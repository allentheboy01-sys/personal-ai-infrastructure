# PDI v0.5.0

## Personal Retrieval Runtime

PDI v0.5.0 turns the v0.4 asset-query MVP into a deployed, evidence-aware
personal retrieval runtime. It preserves provider-independent identity while
adding Resource projection, observations, retrieval, bounded content access,
MCP delivery, and an on-demand reference AI runtime.

## Added

- Stable Resource references and immutable Resource projections.
- Structured recent/search/page queries, aggregation, cursor pagination, and
  captured/file-modified temporal filters.
- Typed Observation statements with lifecycle, evidence, cardinality,
  generator identity, and PostgreSQL persistence.
- Deterministic enrichment for Immich metadata, OCR, provider geo labels, file
  modification time, Nextcloud text, PDF, DOCX, and ODT content.
- Provider-semantic retrieval and rich retrieval across primary text plus
  typed statement filters.
- Bounded, streamed Resource representations through the resource-access
  service.
- Seven read-only MCP Tools: recent, search, aggregate, retrieve, rich
  retrieve, Resource detail, and Resource observations.
- Production synchronization/enrichment timers and resource-access service
  units.
- Validated SSH-on-demand Jarvis/Hermes reference runtime with three approved
  PDI MCP Tools and isolated LLM/PDI credentials.
- Server-first Codex CLI development guidance and repository-level
  `AGENTS.md` continuity.

## Compatibility and boundaries

- The existing provider-independent Asset/Source/Blob identity model remains.
- Observation enrichment does not mutate Resource identity.
- PDI MCP remains read-only.
- Resource access is bounded and credential-isolated; it is not a general
  filesystem interface.
- Jarvis/Hermes and DeepSeek remain replaceable reference components.
- Codex CLI is a development tool and is not part of the PDI production data
  path.
- No general long-term Jarvis memory, write Tool surface, HTTP/Web UI, task
  system, or proactive agent loop is introduced.

## Database changes

The release includes the Observation model migration and query indexes already
present in Alembic. Deployments must run normal schema preflight/migration
procedures before enabling code that requires the new contracts.
